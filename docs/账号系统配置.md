# 站内账号与 Nintendo 绑定

本轮实现三期账号部分：Better Auth 1.6.23 + Workers + D1，使用邮箱一次性验证码自动注册／登录。昵称可留空，留空显示邮箱。站内账号与 Nintendo 绑定均只在 `VITE_SERVER=1` 构建启用，游客普通浏览不发 API 请求。

账号资料、会话、加密 Nintendo 凭据、Coral 缓存、绑定代次及账号冷却保存在 D1。Nintendo 必须在登录站内账号后绑定；同一 Nintendo 账号只能属于一个站内账号。新设备登录同一站内账号即可恢复绑定，后续相册请求按需续期，无需再次粘贴 Nintendo 回调。Nintendo 撤销长期授权或更换加密密钥后仍需重新授权。

自定义头像在浏览器居中裁切成 256 × 256 的静态 WebP，压缩至不超过 100 KiB 后上传；后端检查文件头、尺寸和大小。头像字节保存在 D1，通过当前账号的鉴权接口读取。没有自定义头像时自动使用 Nintendo 头像；重新授权和续期不会覆盖自定义头像。“使用默认头像”会恢复当前 Nintendo 头像，没有绑定时显示文字占位。

## 本地运行

1. 保留现有 `.dev.vars` 中 Nintendo 配置，并加入 `.dev.vars.example` 的账号配置。`COOKIE_KEY` 为随机 32 字节 base64url 密钥，`BETTER_AUTH_SECRET` 使用独立随机密钥且至少 32 字符
2. 为 Resend 验证自有发件域名，将该域名地址填入 `EMAIL_FROM`，密钥填入 `RESEND_API_KEY`。不提供开发环境固定验证码、验证码日志或绕过登录的生产开关
3. 运行 `yarn db:migrate:local` 创建本地 D1 表，再运行 `yarn dev`，在同源页面的「账号与设置」登录

`wrangler.jsonc` 中的 `DB` 已声明为 `gcfp-accounts`。本地迁移不会修改远程数据库，也不会发送邮件。默认发信预算为 UTC 每日 90 封、每月 2900 封，给共用 Resend 免费账号留出余量；可用 `EMAIL_DAILY_LIMIT`／`EMAIL_MONTHLY_LIMIT` 向下调整，允许设为 0 停止新发信。额度不足时已有有效验证码和会话仍可用，不自动升级套餐。

Resend 免费额度及 UTC 自然日重置规则依据[官方额度说明](https://resend.com/docs/knowledge-base/account-quotas-and-limits)。同一 Resend 团队其他应用和收信也会占用供方额度；本站预算仅预占本站请求，供方限额另外明确返回错误。

## 正式部署

1. 使用 `yarn wrangler d1 create gcfp-accounts` 创建远程数据库，将返回的 `database_id` 写入现有 `d1_databases` 项。预览环境使用独立测试库，不共享正式数据
2. 使用 `yarn wrangler secret put` 分别配置 `BETTER_AUTH_SECRET`、`RESEND_API_KEY`、`COOKIE_KEY`，将 `EMAIL_FROM` 放入部署变量或 secret；原 Nintendo 环境配置继续使用
3. 核对所选 D1 后执行 `yarn wrangler d1 migrations apply gcfp-accounts --remote`，再用 `yarn build:server` 构建并部署 Worker
4. 在受控真实邮箱验收送达，再用真实 Nintendo 账号验收授权和续期。本地模拟验收不代表真实邮件或第三方服务已完成联调

认证表迁移 `0001_auth.sql` 从实际库配置生成，业务表在 `0002_accounts.sql`。`yarn auth:schema` 用于查看全新认证表结构，升级已部署数据库时应新建增量迁移，不重新执行初始迁移。自有 API 要求 `X-App-Protocol-Version: 1`，头像图片读取例外；写请求校验同源 Origin。

## 数据和退出行为

每个账号拥有独立的 `groove-archive-fp-account-{userId}` IndexedDB。游客库 `groove-archive-fp-history` 原样保留。切号通过完整刷新重挂载应用，旧账号数据库实例、订阅和识别任务不会复用到新账号；本地存储只保存不含凭据的账号显示资料。会话过期或离线保留原账号数据，重新登录前不启动相册读取。

退出只撤销当前设备会话，返回游客库，保留原账号本机缓存和云端 NS 绑定。解绑撤销该账号的 NS 绑定，其他设备的后续请求和旧票据被拒绝，已经录入的本机成绩保留。旧版浏览器的 Nintendo Cookie 在用户登录并勾选服务端加密存储同意后可迁入账号；事务成功后才清除旧 Cookie，同一迁移 ID 可重试。

本轮没有实现三期的成绩历史 outbox、游客成绩迁移和云端历史同步。成绩、相册处理结果及每日趋势仍各设备本地保存，不应将本站账号登录描述为成绩已跨设备同步。

## 验收

- `yarn check:worker`：Worker 类型检查
- `yarn test:account`／`yarn test:account-runtime`：真实 HTTP、D1 与 Node／Workerd，覆盖验证码、发信预算、账号／绑定隔离、头像、迁移及会话
- `yarn build:server` 后运行 `yarn test:account-browser`：自行启动真实 Worker，使用两个独立浏览器上下文操作登录、资料、NS 绑定、压缩上传和退出，并检查手机布局
- `yarn test:album-worker`／`yarn test:album-runtime`：保留 Nintendo 协议、票据、下载、上游错误与 Origin 回归，增加站内账号登录前置

验收只模拟外部邮件与 Nintendo 服务，不发送真实邮件、不修改线上账号或资源。
