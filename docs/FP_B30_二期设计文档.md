## 3. Excel 使用流程

「偏好设置 → 本地数据」提供「下载模板」「导出成绩」「导入成绩」三个按钮。首页上传区也接受选择或拖入单个 `.xlsx` 文件，复用相同的校验、预览与确认弹窗；成绩截图继续走 OCR。多个 Excel 或 Excel 与截图混选时提示分别上传，不写入数据。

- 模板可在没有成绩时下载，BASIC / ADVANCED 两张表预填当前内置曲库的全部谱面，不需要复制曲库
- 导出读取全部本地成绩，不受成绩页或 B30 页面筛选影响；没有成绩时禁用导出
- 文件在浏览器中读取，选中后只校验和预览，用户点击「确认导入」后才写入
- 预览显示有效行、错误行、空白行，以及预计新增、更新和跳过数量
- 有任何错误都阻止整批导入，显示工作表名称、行号和原因，修正后重新选择文件
- 导入成功显示实际统计，已有列表订阅自动刷新成绩与 B30
- 不保存上传工作簿，不上传到服务器；导出文件不包含截图、偏好或历史记录

## 4. 工作簿规范（版本 3）

SheetJS CE 0.20.3 负责读取，ExcelJS 4.4.0 负责带格式、公式与曲绘的工作簿生成。Excel 模块按需动态加载，不进入首页初始脚本。SheetJS 固定官方 CDN tarball 来源，安装依据：[SheetJS 官方安装文档](https://docs.sheetjs.com/docs/getting-started/installation/nodejs)。

只接受 `.xlsx`，最大 5 MB。只读取 BASIC / ADVANCED 工作表，每张最多 5000 行数据、32 列；超过限制拒绝。表头在前 10 行自动定位，可调整列顺序。必填表头缺失、输入列名重复、工作簿无法解析时直接报错。输入列不接受公式，Rank / RT 的派生公式不作为导入依据。

允许删除标题说明行、未游玩谱面行、参考列及可选输入列，也可删除或清空其中一张模式表，继续读取剩余表的数据。按表头及 Chart ID 关联，不依赖曲绘、合并曲名或固定行号。必须保留 Score 和 Chart ID 两列表头及已填写成绩对应的 Chart ID；Song ID 列或单元格被删除时从内置曲库恢复，不猜测缺失的 Chart ID。

| 列                     | 输入规则                                                                                             |
| ---------------------- | ---------------------------------------------------------------------------------------------------- |
| Song ID                | 输出为文本；删除或留空时按 Chart ID 从内置曲库恢复；有值时须与谱面匹配                               |
| Chart ID               | 必填，属于该 Song ID 的谱面 ID，输出为文本                                                           |
| 曲名、模式、难度、等级 | 参考列；实际数据始终从曲库获取                                                                       |
| Score                  | 0～1,050,000 整数；可读数字或纯数字文本，不接受逗号文本、小数；留空表示不导入，0 是真实成绩          |
| FC、AP                 | 可选，TRUE / FALSE、是 / 否、1 / 0；留空按 false；AP=true 自动补 FC=true，显式 FC=false 时拒绝       |
| Max Chain              | 可选，非负安全整数；留空为未知                                                                       |
| Rank、RT               | 表内随 Score 自动计算；导入时不信任其值，按当前规则重算                                              |
| 更新时间               | 可选；使用导出的 ISO UTC 文本，保留毫秒精度；也可填写整秒格式；不接受 Excel 日期序号；缺失取导入时刻 |

全空行忽略。预填行未填写 Score 时跳过，不能将空分数当作 0。填写分数的行须保留正确的 Chart ID，若提供 Song ID 则须匹配，且谱面模式须与工作表匹配。文件内同一谱面选择最高分；同分选择更新时间最新者，有时间优先于无时间，时间相同或均缺失时选文件最后一行。

模板与成绩导出统一使用两张表：

1. **BASIC**：全部 BASIC 谱面，每首歌按 EASY / NORMAL / HARD / MASTER 展示
2. **ADVANCED**：全部 ADVANCED 谱面，使用相同布局

当前曲库每张表 124 首歌、496 张谱面。曲绘及曲名跨歌曲的四个难度行合并；难度配色、交替底色、冻结曲绘 / 曲名列与表头便于长表填写。Score / FC / AP / Max Chain 为黄色输入区域，Rank / RT 为公式区域；分数及 Max Chain 有整数校验，FC / AP 提供「是 / 否」下拉，非法分数与完成标记冲突显示红色提醒。

更新时间、Chart ID、Song ID 位于 K:M 列，默认隐藏，用于无损读取和关联。顶部说明提示只填写输入区域，不删除隐藏列。曲名按当前日英元数据偏好输出，ID 不变；缺失曲绘保留音符占位。导出预填已有成绩及时间，没有成绩的谱面仍留空，可直接再次导入。

Rank 公式共用现有等级阈值；RT 按相同分数节点以整数百分位插值并截断，避免浮点边界误差。留空时两列为空，0 分计算为 E / 0.00，非法分数显示「检查分数」。

## 5. 导入合并与数据语义

所有输入先校验，Excel 任一有效输入行错误会阻止整批导入。每谱面从文件取最高分，同分按更新时间及行序选取整条记录，不拼接不同候选的完成信息。

- 去重组合为 Chart ID、Score、Max Chain、FC、AP；来源及时间不参与比较。FC/AP 缺省按 false，Max Chain 缺省与 0 不同
- 同批次完全相同的记录只保留一次；跨批次仅与同谱面最近历史比较，按导入时间及历史 ID 判断最近，不与全部历史或当前最佳比较
- Excel 文件内较低分候选不入库；选中的文件最高分即使低于数据库最佳，只要未重复，也保存历史
- 当前最佳从历史按高分优先重放；同分不覆盖已有完成标记，只补未记录的 Max Chain。仅补 Max Chain 不改变最高分记录的更新时间
- 历史记录保存输入字段、来源、导入时间及成绩更新时间，不保存创建时间。Excel 更新时间使用文件值或导入时刻，不影响最近成绩排序
- OCR 每张有效且不重复的截图事务提交；Excel 整批历史、最佳成绩、快照在同一事务提交。预览只估算，提交时再次比较最新数据；失败全回滚
- 预览与通知分别显示录入数、重复跳过数、候选忽略数，以及最佳成绩新增／变化数。纯重复导入不产生快照
- Excel 导出当前最佳和更新时间，不输出历史。曲绘通过模板表头定位 Song ID，不绑定固定列号

## 6. 曲绘来源与复用

曲库只保留 `coverSourceUrl`，删除一期的本地 `coverUrl`。外站 groovecoaster.com / groovecoaster.link 不返回 CORS 头，浏览器可显示但无法读取像素，GitHub Pages 又没有服务端代理，因此改为构建期生成同源缩略图：

- `scripts/prepare-covers.mjs` 在 dev / build 前运行，按来源地址下载，生成 128×128 JPEG（quality 80，mozjpeg）至 `public/covers/`
- 文件名为来源地址的 FNV-1a 哈希（`src/core/song/cover.ts` 与脚本共用），同一曲绘多首歌只存一份；来源地址变更即换新文件名，不会读到旧缓存
- 缩略图约 3～6 KB，原图约 18 KB；当前全曲库 124 张约 670 KB，列表按需懒加载
- `SongCover` 先加载缩略图，失败回退来源原图，再失败显示音符占位
- Excel 导出请求与列表相同的缩略图地址，已显示过的曲绘命中浏览器 HTTP 缓存；JPEG 直接嵌入，无需 canvas 转码；同一会话内的成功结果保存在内存中，重复导出不再请求，失败项下次下载重试
- Excel 同时最多请求 6 张，单张超时 4 秒，整批加载预算 20 秒；同一来源只加载一次，并在两张表及共享曲绘的歌曲间复用图片
- 构建时下载失败只警告：页面回退原图，Excel 该曲保留占位并在完成通知中提示数量

2026-09-29 验证：Edge 中列表加载 128px 同源缩略图，外站请求为 0；当前导出工作簿含 124 张不重复图片，两张表各 124 首歌全部有图。模拟一张缩略图 404 时，两张表均保留占位；恢复后只请求失败的那张，成功项复用缓存；随后再次导出 0 次请求。删除缩略图后列表回退原图正常显示。

## 10. 历史成绩与 Rating 趋势（2026-10-11）

### 10.1 存储与重建

使用新库 `groove-archive-fp-history`，初始 schema 为 1，不读取或迁移旧库。`scoreHistory` 为事实来源，`scores` 为按谱面唯一的当前最佳，`ratingSnapshots` 为双模式曲线快照，`metadata` 保存计算版本。历史使用数字自增 ID，当前最佳通过 historyId 关联提供最佳分数的记录。

`importedAt` 是本次录入时刻，`playedAt` 是历史成绩时间，`updatedAt` 是成绩更新时间，`correctedAt` 标记手动修正。历史 ID 用于同毫秒下的稳定排序，Excel 整批提交，OCR 与相册逐张提交。schema 6 快照使用 `{ id, day, recordedAt, basic, advanced }`，day 唯一，按保存时本地日期固定标记；旧快照按原时间、主键排序后，每天保留最后一条的数值。截图和工作簿仍不持久化。

初始化遇到曲库／规则版本变化时，事务内重算历史 Rating 和当前最佳，不重建过去快照。普通末尾追加增量合并最佳；chartId + playedAt 索引用于判断旧图补录，只重放涉及谱面的历史。修改、删除也只重选该谱面，分数修改同步更新历史 Rating，保留现有同分与 Max Chain 规则。手动编辑原位修正最佳关联历史，保留导入时间及来源，不增加历史条数，降分仍需确认。更新最佳后仅在总 Rating 变化时写入今天，空库不建点，有成绩无快照时建立当前基线。删光历史保留过去趋势，今天按规则记录零 Rating。

### 10.2 页面

成绩管理只保留编辑及歌曲信息。首页、成绩管理、B30 的曲名或封面均打开根部常驻歌曲详情；默认定位所点模式，展示歌曲资料、该模式全部谱面及历史，缺失资料为 `--`。物量详情可展开。历史按导入时间倒序，每页 30 条；单条删除只在此处提供，确认包含曲目、难度、分数、导入时间及重算说明，失败保留记录与错误。

首页最近成绩默认每页 10 条，按成绩时间及 ID 倒序，通过索引读取当前页。其他表头排序订阅当前歌曲／模式的完整匹配历史，复用展示数据与当前排序结果，翻页只截取结果；切换排序或曲目语言复用原始数据，切换范围重新查询，数据变动自动刷新。返回时间排序或关闭视图时释放完整缓存。保留页码修正、加载与错误反馈、重试及过期查询隔离。

设置页清空会同时删除历史、当前最佳和曲线，保留曲库、偏好及计算版本。历史没有自动保留期限，不提供历史备份导出。

### 10.3 趋势

首页显示 Vue + SVG 折线图，与 BASIC／ADVANCED 模式联动，存在快照时即使没有当前成绩也继续展示。提供日／月／年三个粒度，默认日，会话内保留选择；每天最多一条，首次建立基线，之后总 Rating 变化时创建或更新当天记录，当天回落保留最新值，跨天后固定。月／年取周期内最后一条，无记录周期延续前值，首条快照前不补值。按保存的日期标签展示，改变时区不重新分组旧记录。补录、修改、删除和规则升级只影响当前最佳与今天的快照，清空全部数据才删除过去趋势。

## 11. 曲库查询（2026-10-12）

成绩管理页用「已有成绩 / 全部谱面」切换范围，不另开页面。全部谱面列出内置曲库的每一张谱面，已有成绩合并到对应行；未打的谱面 Score、Rank、Rating 和时间为空，不显示成 0。

搜索、分类、模式、难度沿用现有筛选。等级改为上下限，只接受数字和末尾的 +；下限不填按 1，上限不填按 14+，含两端。成绩页和 B30 都使用。B30 只筛选已入选成绩，不列出未打谱面。

成绩页的行以 Chart ID 为唯一键。点击曲名或歌曲信息仍打开现有歌曲信息，并定位到该行的模式。已有成绩继续编辑；未打谱面的操作是录入，打开手动新增并预选这首歌、模式和难度。

角标在全部谱面时写明曲库谱面数和其中已有成绩的数量；有筛选时写当前显示数量。按分数、Rank、Rating 或时间排序时，没有成绩的行固定排在后面，彼此按曲名、模式、难度排列。

## 12. 多语言 UI（2026-10-12）

界面支持简体中文、繁体中文、日文和英文，使用 vue-i18n 11 组合式模式。文案位于 `src/locales/` 的四个 JSON 文件，键结构一致，简体中文为回退语言；`src/i18n.ts` 负责语言列表、浏览器语言匹配与实例创建。组件使用 `useI18n()`，核心模块与组合函数使用全局 `t`；错误以键或状态保存，切换语言后已显示的提示同步更新。英文使用复数形式，其他语言不区分单复数。日期、数字通过 Intl 按当前界面语言格式化；Score 继续固定千分位格式。

| 偏好         | 存储键           | 启动规则                                                                              |
| ------------ | ---------------- | ------------------------------------------------------------------------------------- |
| 界面语言     | `ga-ui-language` | 已保存值优先；否则按 `navigator.languages` 顺序匹配首个支持的语言；均不匹配用简体中文 |
| 曲目信息语言 | `ga-language`    | 已保存值优先；首次访问按界面语言联动：英文 → 英文元数据，其他 → 日文元数据            |

匹配规则：`zh-Hant`、`zh-TW`、`zh-HK`、`zh-MO` 归为繁体中文，其他 `zh` 归为简体中文，`ja`、`en` 开头分别归为日文、英文。界面语言只在用户切换后保存；切换界面语言时重新联动曲目信息语言，之后单独切换曲目信息语言不影响界面语言。没有存储权限时仅本次会话生效。`<html lang>` 与页面标题随界面语言更新。

Excel 模板、导出文件名、表头及单元格输入提示随界面语言输出；导入仍接受全部语言的表头，内部字段名不变。曲库的歌曲名、歌手、分类与曲包仍由曲目信息语言决定，不随界面翻译。Node 环境固定简体中文，XLSX 文件验收的报错文本保持稳定。

验收：`yarn test:ui` 在界面中依次切换四种语言并检查曲目信息语言联动与 `<html lang>`；以 ja-JP、zh-HK、en-US、fr-FR 浏览器语言首次访问，分别得到日文、繁体中文、英文与简体中文界面；保存日文界面并单独切换为英文曲目信息后刷新，两项均保留。`yarn test:excel` 在四种界面语言下实际下载模板与成绩，检查本地化文件名与表头，并在另一种语言界面中重新导入。其他浏览器验收固定以 zh-CN 环境启动。
