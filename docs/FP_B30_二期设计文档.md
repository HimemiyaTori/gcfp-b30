## 3. Excel 使用流程

「偏好设置 → 本地数据」提供「下载导入模板」「导出全部成绩」「导入 Excel」三个按钮。首页上传区也接受选择或拖入单个 `.xlsx` 文件，复用相同的校验、预览与确认弹窗；成绩截图继续走 OCR。多个 Excel 或 Excel 与截图混选时提示分别上传，不写入数据。

- 模板可在没有成绩时下载，BASIC / ADVANCED 两张表预填当前内置曲库的全部谱面，不需要复制曲库
- 导出读取全部本地成绩，不受成绩页或 B30 页面筛选影响；没有成绩时禁用导出
- 文件在浏览器中读取，选中后只校验和预览，用户点击「确认导入」后才写入
- 预览显示有效行、错误行、空白行，以及预计新增、更新和跳过数量
- 有任何错误都阻止整批导入，显示工作表名称、行号和原因，修正后重新选择文件
- 导入成功显示实际统计，已有列表订阅自动刷新成绩与 B30
- 不保存上传工作簿，不上传到服务器；导出文件不包含截图、偏好或历史记录

## 4. 工作簿规范（版本 2）

SheetJS CE 0.20.3 负责读取，ExcelJS 4.4.0 负责带格式、公式与曲绘的工作簿生成。Excel 模块按需动态加载，不进入首页初始脚本。SheetJS 固定官方 CDN tarball 来源，安装依据：[SheetJS 官方安装文档](https://docs.sheetjs.com/docs/getting-started/installation/nodejs)。

只接受 `.xlsx`，最大 5 MiB。只读取 BASIC / ADVANCED 工作表，每张最多 5000 行数据、32 列；超过限制拒绝。表头在前 10 行自动定位，可调整列顺序，不兼容旧版「成绩」表。必填表头缺失、输入列名重复、工作簿无法解析时直接报错。输入列不接受公式，Rank / RT 的派生公式不作为导入依据。

允许删除标题说明行、未游玩谱面行、参考列及可选输入列，也可删除或清空其中一张模式表，继续读取剩余表的数据。按表头及 Chart ID 关联，不依赖曲绘、合并曲名或固定行号。必须保留 Score 和 Chart ID 两列表头及已填写成绩对应的 Chart ID；Song ID 列或单元格被删除时从内置曲库恢复，不猜测缺失的 Chart ID。

| 列 | 输入规则 |
| --- | --- |
| Song ID | 输出为文本；删除或留空时按 Chart ID 从内置曲库恢复；有值时须与谱面匹配 |
| Chart ID | 必填，属于该 Song ID 的谱面 ID，输出为文本 |
| 曲名、模式、难度、等级 | 参考列；实际数据始终从曲库获取 |
| Score | 0～1,050,000 整数；可读数字或纯数字文本，不接受逗号文本、小数；留空表示不导入，0 是真实成绩 |
| FC、AP | 可选，TRUE / FALSE、是 / 否、1 / 0；留空为未知；AP=true 自动补 FC=true，显式 FC=false 时拒绝 |
| Max Chain | 可选，非负安全整数；留空为未知 |
| Rank、RT | 表内随 Score 自动计算；导入时不信任其值，按当前规则重算 |
| 创建时间、更新时间 | 可选；使用导出的 ISO UTC 文本，保留毫秒精度；也可填写整秒格式；不接受 Excel 日期序号；创建时间不能晚于更新时间 |

全空行忽略。预填行未填写 Score 时跳过，不能将空分数当作 0。填写分数的行须保留正确的 Chart ID，若提供 Song ID 则须匹配，且谱面模式须与工作表匹配。文件内重复谱面报错并指出先前工作表及行号，不隐式挑选某一行。

模板与成绩导出统一使用两张表：

1. **BASIC**：全部 BASIC 谱面，每首歌按 EASY / NORMAL / HARD / MASTER 展示
2. **ADVANCED**：全部 ADVANCED 谱面，使用相同布局

当前曲库每张表 124 首歌、496 张谱面。曲绘及曲名跨歌曲的四个难度行合并；难度配色、交替底色、冻结曲绘 / 曲名列与表头便于长表填写。Score / FC / AP / Max Chain 为黄色输入区域，Rank / RT 为公式区域；分数及 Max Chain 有整数校验，FC / AP 提供「是 / 否」下拉，非法分数与完成标记冲突显示红色提醒。

创建时间、更新时间、Chart ID、Song ID 位于 K:N 列，默认隐藏，用于无损读取和关联。顶部说明提示只填写输入区域，不删除隐藏列。曲名按当前日英元数据偏好输出，ID 不变；缺失曲绘保留音符占位。导出预填已有成绩及时间，没有成绩的谱面仍留空，可直接再次导入。

Rank 公式共用现有等级阈值；RT 按相同分数节点以整数百分位插值并截断，避免浮点边界误差。留空时两列为空，0 分计算为 E / 0.00，非法分数显示「检查分数」。

## 5. 导入合并与数据语义

第一版只提供保留高分的合并，不提供 Excel 批量降分或全库替换；纠错降分继续使用现有编辑确认流程。

| 当前成绩与输入关系 | 行为 |
| --- | --- |
| 新谱面 | 新增，计算 Rating，保留提供的创建 / 更新时间，缺失时间按可用时间或导入时刻补齐 |
| 输入分数更高 | 更新分数及本行完成信息，保留原创建时间；更新时间使用提供值或当前时刻，不能早于原创建时间 |
| 输入分数更低 | 整行跳过，不修改任何信息 |
| 同分 | 只补充未知 FC / AP / Max Chain；已有 false、true、0 或非零值均不覆盖；不引入 AP=true / FC=false 冲突 |
| 同分且未补充信息 | 跳过，保留来源与时间 |

实际新增或修改的记录来源设为 `excel`；仅补 Max Chain 不改变更新时间，补 FC / AP 使用导入时刻。不同分数的完成标记随对应分数一起更新，不能把低分的 FC / AP 自动套到更高分。

预览是当时状态的估算。提交时在一个读写事务中重新读取当前记录、校验并合并，避免并发 OCR / 手动操作造成低分覆盖。任何校验或写入失败均回滚整批；最终通知使用实际统计。数据库仍使用现有表及索引，增加 source 联合类型值，无新增表或 schema 版本迁移。

## 6. 曲绘来源与复用

曲库只保留 `coverSourceUrl`，删除一期的本地 `coverUrl`。外站 groovecoaster.com / groovecoaster.link 不返回 CORS 头，浏览器可显示但无法读取像素，GitHub Pages 又没有服务端代理，因此改为构建期生成同源缩略图：

- `scripts/prepare-covers.mjs` 在 dev / build 前运行，按来源地址下载，生成 128×128 JPEG（quality 80，mozjpeg）至 `public/covers/`
- 文件名为来源地址的 FNV-1a 哈希（`src/core/song/cover.ts` 与脚本共用），同一曲绘多首歌只存一份；来源地址变更即换新文件名，不会读到旧缓存
- 缩略图约 3～6 KB，原图约 18 KB；当前全曲库 124 张约 670 KB，列表按需懒加载
- `SongCover` 先加载缩略图，失败回退来源原图，再失败显示音符占位
- Excel 导出请求与列表相同的缩略图地址，已显示过的曲绘命中浏览器 HTTP 缓存；JPEG 直接嵌入，无需 canvas 转码；同一会话内的成功结果保存在内存中，重复导出不再请求，失败项下次下载重试
- Excel 同时最多请求 6 张，单张超时 4 秒，整批加载预算 20 秒；同一来源只加载一次，并在两张表及共享曲绘的歌曲间复用图片
- 构建时下载失败只警告：页面回退原图，Excel 该曲保留占位并在完成通知中提示数量

2026-09-29 验证：Edge 中列表加载 128px 同源缩略图，外站请求为 0；当前导出工作簿含 124 张不重复图片，两张表各 124 首歌全部有图。模拟一张缩略图 404 时，两张表均保留占位；恢复后只请求失败的那张，成功项复用缓存；随后再次导出 0 次请求。删除缩略图后列表回退原图正常显示。
