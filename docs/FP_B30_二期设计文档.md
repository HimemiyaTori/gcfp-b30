## 3. Excel 使用流程

入口为「偏好设置 → 本地数据」。提供「下载导入模板」「导出全部成绩」「导入 Excel」三个按钮。

- 模板可在没有成绩时下载，曲库对照跟随当前内置曲库生成
- 导出读取全部本地成绩，不受成绩页或 B30 页面筛选影响；没有成绩时禁用导出
- 文件在浏览器中读取，选中后只校验和预览，用户点击「确认导入」后才写入
- 预览显示有效行、错误行、空白行，以及预计新增、更新和跳过数量
- 有任何错误都阻止整批导入，显示工作表行号和原因，修正后重新选择文件
- 导入成功显示实际统计，已有列表订阅自动刷新成绩与 B30
- 不保存上传工作簿，不上传到服务器；导出文件不包含截图、偏好或历史记录

## 4. 工作簿规范（版本 1）

使用 SheetJS CE 0.20.3，固定官方 CDN tarball 来源，按需动态加载，不进入首页初始脚本。安装依据：[SheetJS 官方安装文档](https://docs.sheetjs.com/docs/getting-started/installation/nodejs)。

只接受 `.xlsx`，最大 5 MiB。「成绩」工作表最多 5000 行数据、32 列；超过限制拒绝。只读取名为「成绩」的工作表，表头必须在第 1 行，可调整列顺序。必填表头缺失、输入列名重复、工作簿无法解析时直接报错。公式不执行，数据行包含公式时要求先粘贴为值。

| 列 | 输入规则 |
| --- | --- |
| Song ID | 必填，对应内置曲库歌曲 ID，输出为文本 |
| Chart ID | 必填，属于该 Song ID 的谱面 ID，输出为文本 |
| 曲名、模式、难度、等级 | 参考列；实际数据始终从曲库获取 |
| Score | 必填，0～1,050,000 整数；可读数字或纯数字文本，不接受逗号文本、小数、空值 |
| FC、AP | 可选，TRUE / FALSE、是 / 否、1 / 0；留空为未知；AP=true 自动补 FC=true，显式 FC=false 时拒绝 |
| Max Chain | 可选，非负安全整数；留空为未知 |
| Rank、Rating | 参考列，不信任导入值；按当前规则重算 |
| 创建时间、更新时间 | 可选；使用导出的 ISO UTC 文本，保留毫秒精度；也可填写整秒格式；不接受 Excel 日期序号；创建时间不能晚于更新时间 |

全空行忽略。填写了 ID 的行必须填写 Score，不能将空分数当作 0。文件内重复谱面报错并指出先前行号，不隐式挑选某一行。

模板包含四张表：

1. **成绩**：仅表头，用户在此填写实际成绩
2. **说明**：字段、合并行为、限制与填写方法
3. **曲库对照**：所有谱面的 ID、曲名、模式、难度与等级，可复制前六列至成绩表
4. **示例（不导入）**：演示填写方式，不作为真实成绩自动导入

导出文件包含「成绩」与「说明」，可直接再次导入。曲名按当前日英元数据偏好输出，ID 不变。

## 5. 导入合并与数据语义

第一版只提供保留高分的合并，不提供 Excel 批量降分或全库替换；纠错降分继续使用现有编辑确认流程。

| 当前成绩与输入关系 | 行为 |
| --- | --- |
| 新谱面 | 新增，计算 Rating，保留提供的创建 / 更新时间，缺失时间按可用时间或导入时刻补齐 |
| 输入分数更高 | 更新分数及本行完成信息，保留原创建时间；更新时间使用提供值或当前时刻，不能早于原创建时间 |
| 输入分数更低 | 整行跳过，不修改任何信息 |
| 同分 | 只补充未知 FC / AP / Max Chain；已有 false、true、0 或非零值均不覆盖；不引入 AP=true / FC=false 冲突 |
| 同分且未补充信息 | 跳过，保留来源与时间 |

实际新增或修改的记录来源设为 `excel`；仅补 Max Chain 不改变更新时间，补 FC / AP 使用导入时刻。不同分数的完成标记随对应分数一起更新，不能把低分的 FC / AP 自动套到更高分。

预览是当时状态的估算。提交时在一个读写事务中重新读取当前记录、校验并合并，避免并发 OCR / 手动操作造成低分覆盖。任何校验或写入失败均回滚整批；最终通知使用实际统计。数据库仍使用现有表及索引，增加 source 联合类型值，无新增表或 schema 版本迁移。

## 6. 曲绘来源与复用

曲库只保留 `coverSourceUrl`，删除一期的本地 `coverUrl`。外站 groovecoaster.com / groovecoaster.link 不返回 CORS 头，浏览器可显示但无法读取像素，GitHub Pages 又没有服务端代理，因此改为构建期生成同源缩略图：

- `scripts/prepare-covers.mjs` 在 dev / build 前运行，按来源地址下载，生成 128×128 JPEG（quality 80，mozjpeg）至 `public/covers/`
- 文件名为来源地址的 FNV-1a 哈希（`src/core/song/cover.ts` 与脚本共用），同一曲绘多首歌只存一份；来源地址变更即换新文件名，不会读到旧缓存
- 缩略图约 3～6 KB，原图约 18 KB；全曲库 123 张约 670 KB，列表按需懒加载
- `SongCover` 先加载缩略图，失败回退来源原图，再失败显示音符占位
- Excel 导出请求与列表相同的缩略图地址，已显示过的曲绘命中浏览器 HTTP 缓存；JPEG 直接嵌入，无需 canvas 转码；同一会话内的导出结果保存在内存中，重复导出不再请求
- 构建时下载失败只警告：页面回退原图，Excel 该曲保留占位并在完成通知中提示数量

2026-09-29 验证：Edge 中列表加载 128px 同源缩略图，外站请求为 0；导出工作簿含 123 张不重复图片，BASIC 表 124 首歌全部有图；同一会话第二次导出 0 次请求；删除缩略图后列表回退原图正常显示。
