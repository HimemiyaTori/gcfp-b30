# 侧边栏展开与收起：实现经验

记录日期：2026-09-24。基于 Nageki-Net 页面观察与本项目实际改造。

这类动画需要同时处理布局、内容显隐和操作反馈。最影响观感的是这些变化是否协调：侧栏边界和正文同步移动，文字在空间不足前退场，图标保持尺寸，按钮能在动画途中再次响应。

## 1. 参考来源与证据边界

参考页面：[Nageki-Net](https://next.nageki-net.com/net/welcome)。访问时跳转到了登录页，本次观察的是登录页可操作的公共侧栏。

通过展开、收起、调整视口，以及读取 DOM 的类名、内联样式和计算样式，确认了以下信息：

| 项目     | Nageki-Net 观察结果                                                                   | 本项目采用方式                                              |
| -------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 桌面侧栏 | 展开宽度 286px，收起宽度 76px                                                         | 保留自身比例：230px／205px → 78px                           |
| 正文布局 | `margin-left` 随侧栏宽度变化                                                          | 侧栏和正文使用同一个宽度变量、时长和曲线                    |
| 文字     | 观察到用户信息文字 `opacity: 1 → 0`、`translateX(0 → -8px)`                           | 将同类处理应用到品牌文字、菜单文字、说明和语言选项          |
| 动画标记 | 宽度及正文元素上有 `easing="outQuint"`；文字退场有 `inQuad` 标记                      | 用 CSS 曲线实现快速响应、缓慢结束的近似观感                 |
| CSS 过渡 | 读到 `400ms cubic-bezier(0.25, 0.8, 0.25, 1)`；涉及抽屉 transform、正文 margin 等属性 | 主布局选用 400ms，但曲线为 `cubic-bezier(0.22, 1, 0.36, 1)` |
| 窄屏     | 观察到宽度 292px 的覆盖式抽屉                                                         | 保留项目原有手机底部导航                                    |
| 组件痕迹 | DOM 中存在 `mat-sidenav`、`mat-drawer` 等类名                                         | 沿用当前组件结构，无需引入同一套 UI 库                      |

**不能把上述 CSS 的 400ms 当成参考站所有动画的真实时长。** 桌面切换过程中还观察到动态变化的内联宽度；本次没有拿到其完整动画调用、关键帧和调度代码。`easing` 属性本身也不足以证明实际执行曲线。因此本文借鉴的是已观察到的行为；本项目时序是自己的实现选择，不追求复刻 nageki 的实现。

## 2. 先分清动画改变什么

### 占据布局空间的侧栏

桌面侧栏收起后，正文应获得更多空间。这需要改变实际布局。本项目使用固定定位的侧栏，正文通过左外边距让出空间：

```css
.app-shell {
    --sidebar-width: 230px;
    --sidebar-duration: 400ms;
    --sidebar-ease: cubic-bezier(0.22, 1, 0.36, 1);
}

.sidebar {
    width: var(--sidebar-width);
    transition:
        width var(--sidebar-duration) var(--sidebar-ease),
        padding var(--sidebar-duration) var(--sidebar-ease);
}

.workspace {
    margin-left: var(--sidebar-width);
    transition: margin-left var(--sidebar-duration) var(--sidebar-ease);
}

@media (min-width: 681px) {
    .sidebar-collapsed {
        --sidebar-width: 78px;
    }
}
```

宽度变量提供统一终点，两个属性各自执行过渡。此处没有给自定义属性本身做动画。

只改侧栏宽度、延后再移动正文，会出现缝隙或遮挡。即使两者同时开始，只要曲线、时长不一致，中间帧仍可能错开。还要把边框和内边距计入宽度，本项目全局采用 `box-sizing: border-box`。

### 覆盖正文的抽屉

覆盖式抽屉通常只需平移侧栏，并配合遮罩显隐；正文可以保持原位。不要为了套用桌面方案让手机正文跟着压缩。本项目在 680px 及以下直接使用底部导航，这是独立的布局模式。

## 3. 布局同时启动，文字分阶段进出

文字与布局不必采用同一时长。收起时文字尽快退出，展开时先给文字腾出空间，再让它出现。

本项目正常完整切换的时间线如下，快速反向切换时浏览器会从当前过渡值继续：

| 时间  | 收起                                       | 展开                               |
| ----- | ------------------------------------------ | ---------------------------------- |
| 0ms   | 布局开始收缩；文字立即开始淡出和左移       | 布局开始扩张；文字仍透明，等待入场 |
| 100ms | 文字透明度到 0                             | 布局继续扩张                       |
| 140ms | 文字左移到 -8px；切为 `visibility: hidden` | 文字开始淡入并回到原位             |
| 320ms | 布局继续缓慢收尾                           | 文字透明度到 1                     |
| 380ms | 布局接近终点                               | 文字位移完成                       |
| 400ms | 布局完成                                   | 布局完成                           |

对应代码：

```css
.sidebar-copy {
    white-space: nowrap;
    flex-shrink: 0;
    opacity: 1;
    transform: translateX(0);
    visibility: visible;
    transition:
        opacity 180ms ease-out 140ms,
        transform 240ms var(--sidebar-ease) 140ms,
        visibility 0s;
}

.sidebar-collapsed .sidebar-copy {
    opacity: 0;
    transform: translateX(-8px);
    visibility: hidden;
    pointer-events: none;
    transition:
        opacity 100ms ease-in,
        transform 140ms ease-in,
        visibility 0s 140ms;
}
```

这里的 `visibility` 是延迟执行的离散切换，不是渐变。文字节点继续占据布局空间，可以避免菜单突然上移、图标突然居中。`white-space: nowrap` 避免中途换行，`flex-shrink: 0` 避免内容被压扁，外层裁切负责约束显示范围。

这是一项取舍：收起后仍保留标题和说明的占位，因此菜单纵向位置稳定。如果产品希望收起后同时回收这部分高度，就需要为高度另做设计，不能在中途直接删除节点。

这些时间和位移量是本项目的起点参数。应结合实际宽度差、文字长度和帧率调整，不需要机械照搬。

## 4. 图标稳定，位置变化连续

原实现收起时切换 `justify-content`、隐藏文字，并改变菜单上边距。这些变化会让图标瞬间跳到另一个位置，即使侧栏宽度本身在过渡，仍会显得卡顿。

本次处理原则：

- 图标不缩放，品牌图标也明确设为 `flex-shrink: 0`。
- 导航项始终使用同一种对齐结构，通过可插值的 `padding` 调整图标位置。
- 品牌与菜单保持纵向占位，避免收起时整组导航上跳。
- 隐藏文字留在结构中，图标保持同一个 DOM 节点。

“图标稳定”指尺寸和运动轨迹稳定，不要求屏幕坐标完全不变。本项目收起时图标会随内边距轻微移动到窄栏中心。

底部控件也需要同样处理。直接将 `flex-direction: row` 切为 `column` 不会产生连续的排列动画。当前只有三个固定按钮，因此使用定位容器：

- 容器高度从 44px 过渡到 140px。
- 按钮保留相同节点，分别过渡 `left`、`bottom`。
- 收起后按钮纵向间隔为 48px，命中区域保持 44 × 44px。
- 展开／收起箭头使用同一 SVG，旋转 180°，避免替换两个图标造成跳变。

定位适合这种少量、固定尺寸的控件。若以后按钮数量动态变化，应重新选择能适应内容的布局方式，必要时采用测量前后位置的动画方案，避免不断追加硬编码坐标。

## 5. 状态只表示目标，动画负责过程

本次移除了“目标收起”“实际收起”“文字可见”三个状态之间的定时器编排，保留一个 `sidebarCollapsed`。

切换时立刻更新根节点 class。宽度、文字、按钮和箭头分别通过 CSS 响应同一个目标状态。这样连续点击时没有旧定时器在稍后覆盖新状态，也不需要等动画结束才能再次操作。

CSS transition 可以从当前计算值转向新的目标值，但这不代表所有快速反向切换都严格耗时 400ms，或一定保持速度连续。带延迟的文字动画也需要实际检查反向切换的观感。

只有当流程确实需要知道动画是否结束，例如退出后卸载节点，才额外引入生命周期或结束事件。不要为单纯的折叠布局制造多套互相同步的状态。

## 6. 响应式与可访问性属于动画设计

当前响应式规则：

| 视口         | 行为                                     |
| ------------ | ---------------------------------------- |
| 大于 1200px  | 展开宽度 230px                           |
| 681–1200px   | 展开宽度 205px                           |
| 桌面侧栏收起 | 宽度 78px                                |
| 960px 及以下 | 初始化及跨越该断点时，设置为收起目标     |
| 680px 及以下 | 底部导航，正文左外边距归零，关闭布局过渡 |

文字隐藏规则只放在桌面媒体查询中，避免手机仍保留 `sidebar-collapsed` 状态时，底部菜单文字一起消失。跨越 960px 会重设折叠状态，这是当前行为；若未来要保留用户手动选择，需要单独定义“自动响应式”和“用户偏好”的优先级。

可访问性注意点：

- 图标模式的导航保留 `aria-label`，并提供悬停标题；品牌链接也有独立名称。
- 折叠按钮通过 `aria-expanded` 和名称表达当前目标及下一步操作。
- `opacity: 0` 不会让控件退出键盘导航；`pointer-events: none` 只影响指针。当前退场结束后以 `visibility: hidden` 隐藏整组语言控件。
- 当前展开时 `visibility` 立即恢复，文字淡入有 140ms 延迟。这段时间控件可能已可聚焦但仍透明，是后续键盘验收要检查的细节。
- 如果在语言按钮持有焦点时通过窗口变化触发隐藏，应检查焦点落点，必要时将焦点移到仍可见的合理位置。这不是当前实现已完成的焦点管理能力。
- 项目已有 `prefers-reduced-motion: reduce` 规则，关闭 transition 和 animation，直接呈现终态，无需等待定时器。

## 7. 性能与实现边界

`width`、`margin-left`、`padding`、`left`、`bottom` 的动画会涉及布局，不能因为用了 CSS 就称其为“纯 GPU 动画”。桌面正文确实需要重新获得空间，因此这里接受布局变化；文字和箭头则使用 `opacity`、`transform`。

优化顺序应是先检查实际负载，再决定是否增加复杂方案：

1. 只为必要属性设置 transition，避免 `transition: all`。
2. 不在每一帧同时读取布局再写入样式。
3. 不为长表格的每一行追加跟随侧栏的动画。
4. 用真实数据量、长页面和较慢设备检查卡顿，再考虑减少重排影响。

当前未进行帧率或性能轨迹分析，不能仅凭截图和构建成功宣称无掉帧。

另一个已知边界是 B30 数量角标：当前仍在收起态切换为绝对定位，并非完整的连续位置动画。当前示例有 32 条成绩，未触发“小于 30 条”的角标显示条件，因此此次普通页面验证没有覆盖它。后续应在 1–29 条成绩时单独检查，必要时统一两态定位或为角标单独设计显隐。

## 8. 常见问题与处理方式

| 现象                       | 常见原因                           | 处理方式                               |
| -------------------------- | ---------------------------------- | -------------------------------------- |
| 宽度在动，图标却突然跳动   | 同时改了对齐方式、节点显示或外边距 | 保留结构，用 padding／位置属性连续过渡 |
| 文字被挤成多行             | 可收缩文字参与窄宽度布局           | 不换行、不压缩，单独淡出并裁切         |
| 正文与侧栏之间短暂露缝     | 两处宽度、时长或曲线不一致         | 共用变量与时序，并检查中间帧           |
| 快速点击后文字状态不对     | 多个状态和旧定时器相互覆盖         | 单一目标状态，允许当前过渡反向         |
| 底部按钮横排瞬间变竖排     | 依赖 flex-direction 切换           | 固定少量按钮采用连续位置变化           |
| 手机菜单没有文字           | 桌面隐藏规则作用到移动导航         | 限定媒体查询，单独定义手机终态         |
| 隐藏按钮仍能被 Tab 选中    | 仅设置 opacity 或 pointer-events   | 隐藏终态与键盘语义一同设计             |
| 读到异常宽度，以为布局坏了 | 在动画进行中采样                   | 中间帧与稳定终态分别检查               |

## 9. 验证方法与本次完成范围

建议按以下顺序验收：

1. **终态**：展开与收起后，侧栏宽度应与正文让出的空间一致；文字、图标、按钮均无裁切或重叠。
2. **过程**：检查刚开始、文字退场／入场附近以及收尾阶段。不要只看两张终态截图。
3. **打断**：收起途中展开、展开途中收起、连续点击，检查最终目标和显示内容一致。
4. **响应式**：覆盖宽屏、中等窗口、默认收起区间、手机底部导航，以及切换断点时的状态。
5. **交互与内容**：Tab 导航、隐藏时持有焦点、长文字、数量角标、短窗口、页面滚动。
6. **偏好与性能**：开启减少动态效果；用长表格与真实数据检查运动和负载。
7. **工程检查**：类型检查、生产构建和 diff 空白检查；这些不能替代视觉与交互验收。

本次已完成：桌面展开／收起截图和终态尺寸检查（230px、78px）、连续反向切换操作、中等窗口 205px 终态检查、手机底部导航截图与菜单文字可见性检查，以及类型检查、生产构建、`git diff --check`。

本次未完成：逐帧录制、性能分析、系统减少动态效果的实际切换、完整键盘焦点验收、短窗口和数量角标场景。相关行为不能仅依据代码推断为已验证。
